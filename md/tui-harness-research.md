# Как эталонные harness ведут задачи в TUI, и где у нас разрыв

Исследование по OpenCode, Claude Code, Kimi Code CLI и Codex CLI (источники —
документация и исходники, ноябрь 2026). Запрос: «агент берёт задачу,
обрабатывает, передаёт сабагентам, строит todo — как это видно в TUI».

## Эталоны

**Claude Code.** Модель ведёт чек-лист сама через TodoWrite/TaskCreate/
TaskUpdate; список виден всегда (Ctrl-T), статусы pending/in-progress/
completed. Сабагенты через Task — дочерний контекст, итог возвращается
родителю. Рассуждения (thinking) рендерятся как сворачиваемые блоки.

**OpenCode.** Сайдбар: секция сабагентов — каждая строка показывает, что
сабагент делает прямо сейчас (текущий инструмент и цель, `read: src/foo.ts`,
`bash: bun test`, `retrying 2`); клик открывает дочернюю сессию. Todo —
session task tool, список живёт в транскрипте; плагин 2-tasks делает его
постоянным в сайдбаре. Делегирование — обычный tool call с description в
3–5 слов; глубина сабагентов ограничена (по умолчанию 1).

**Kimi Code CLI.** Главный агент планирует и диспетчерит сабагентов в
изолированных контекстах; план-режим (Shift-Tab) сначала выводит план
исследования. Лента: ввод, разговор, статус-бар; сабагент возвращает выводы
родителю.

**Codex CLI.** Plan mode стримит предложенный план тегами `<proposed_plan>`,
TUI рендерит его как чек-лист с приглашением «Implement this plan?»; план
сохраняется и переживает resume. Рассуждения видны как summary-ячейки в
истории.

## Что у нас уже есть

- План как вкладка со статусами задач, доски задач/находок, гипотезы в графе
  (record_fact/close_intent), сабагенты через agent_spawn и swarm, стрип
  «agents running/total», drill-down в карточку агента/задачи (PR #99).

## Разрыв (по убыванию боли)

1. **Рассуждения модели между вызовами инструментов не показываются.**
   `chat.py`: ответ с tool_calls запоминается, но не печатается — оператор
   видит блоки инструментов без «почему». У всех эталонов это видно.
   → Печатать промежуточный текст хода (обычным сообщением, до блоков).
2. **Сабагент — счётчик, а не живая строка.** У OpenCode у каждого сабагента
   видно текущее действие. У нас — только running/total и tooltip.
   → Стрип/панель: строка на активного агента с текущим инструментом
   (данные есть в событиях tool.run.*), клик → его карточка.
3. **Гипотезы не видны.** Лог гипотез CTF живёт в графе, в TUI нигде.
   → Секция «Гипотезы» во вкладке Ход или в доске: открытые интенты и
   их исходы.
4. **Чек-лист не принадлежит модели.** Наш план статичен: модель не может
   пометить/добавить подзадачу хода. У эталонов список пишет модель.
   → Минимум: record_fact/close_intent уже ближе всего к «todo модели» —
   показать их как живой список шагов хода в журнале.
5. **Plan mode без видимого предложения плана.** У Codex план — ячейка с
   вопросом «реализовать?». У нас plan mode — только запрет на запись.
   → В plan mode печатать предложенный план блоком (уже есть текст ответа).

## Не копируем

- Глубину сабагентов >1 у OpenCode — у нас лестница импакта уже держит рамки.
- Чек-лист Codex как отдельный протокол — наш план сильнее (гейты, scope).
