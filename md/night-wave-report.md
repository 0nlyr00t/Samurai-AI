# Ночная волна: что сделано и чем это проверено

Отчёт для утреннего разбора. Кратко: харнесс получил операционный слой (туннели,
удалённое администрирование, виртуалки, эксплойты), предохранители от
зависаний и лупов, лестницу импакта и пул генов с гейтом. Всё влито в `main`
отдельными PR, каждый — на зелёных проверках.

## Что теперь умеет агент

- **Туннель к любой TCP-цели** (`execution/tunnel.py`): localhost-порт на одну
  in-scope цель, вердикт до первого байта, событие в egress, счётчики объёма,
  дедлайн простоя, лимит соединений.
- **Удалённое администрирование** поверх туннеля: `remote.ssh-exec` (Linux и
  macOS, ключ из vault), `remote.smb-list`, `remote.rdp-check`, `remote.adb`.
- **Виртуалки и диски**: `vm.control` (VBox/libvirt, снимки), `vm.disk`
  (qemu-img) — хостовыми бинарями с закрытым argv.
- **Эксплойты**: `exploit.analyze`, `exploit.build`, `exploit.run`, шаблоны в
  `assets/exploits`.
- **Предохранители**: сквозной дедлайн прогона (900 с по умолчанию, ключ
  `agent.max_wall_seconds`), сторож тишины с профильным таймаутом (nmap 600,
  браузер и белт 300), пометка `[repeats]` модели на третьем одинаковом вызове.
- **Лестница импакта**: уровни `read → rce` с баллами, порог отчётности,
  бюджет, бамп `evidence_version`; модель поднимает уровень сама командой
  `record_impact`, оператор — `finding impact`; отчёт показывает оценку и может
  отказать по порогу (`report generate --min-impact`).
- **Гены**: версии, фитнес из отчёта eval, гейт `shadow → active` с откатом;
  активные гены идут в промпт планировщика и исполнителя.

## Чем проверено

- `uv run pytest -q` → 1118 тестов зелёные, 12 skip.
- `SAMURAI_TEST_DOCKER=1 uv run pytest tests/integration/test_sandbox_docker.py`
  → 10 живых прогонов: sshd, Samba и xrdp как цели, подъём и уборка контейнеров.
- Живые ручные прогоны: ssh `id -un` → `ops`; smb list → `share`;
  `remote.rdp-check` → `exit status 0`; `qemu-img info`; поиск и чтение через
  браузер; eval-smoke трижды без регрессий (`eval compare` чист).
- ruff и strict mypy — зелёные на каждом PR.

## Чего не проверено (честно)

- **ADB** — только mock-прогоны: на arm64 Mac эмулятор не поднять без боли.
- **VBoxManage** — на этой машине стоит только `qemu-img`, virtulbox-ветка
  проверена mock-ами.
- **Гены в поле** — влияние на качество прогонов требует серии eval с ключами;
  механика (фитнес, гейт, откат, вставка в промпт) покрыта тестами.
- **RDP с настоящей аутентификацией** — проба намеренно `/auth-only`.

## Решения, которые стоит пересмотреть с холодной головой

1. **ops-профиль без root.** Белт сейчас на nobody и без сети вне прокси, но
   белт в 748 МБ и собран локально: пересборка меняет digest профиля, и его надо
   перепинивать. Правильнее — публиковать образ в реестр из CI.
2. **Вердикт туннеля один на соединение** и не переопределяется. Для SMB/RDP это
   нормально, для инструментов с редиректами — может оказаться тесно.
3. **`xvfb` в белте** появился ради `/auth-only`; если RDP-проба станет
   интерактивной, этого не хватит.
4. **Гены в файле, а не в журнале** — быстро, но аудит пула слабее остальных
   сущностей.
